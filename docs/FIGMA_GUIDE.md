# Figma 활용 가이드 — KB 부스 웹앱

작성: 2026-05-10

현재 Figma Make로 잡혀있는 디자인을 어떻게 코드로 가져와 쓸 건지, 그리고 지금 단계에서 추가로 보강 요청해야 할 화면은 무엇인지 정리.

## 1. Figma에 추가 요청할 보강 사항

현재 10개 화면 중 콘텐츠·스펙 변경이 들어간 3개 화면을 다시 돌릴 차례. 아래 프롬프트를 그대로 Figma Make에 추가 요청으로 넣으면 됨.

### 1.1 화면 6 — 결과 공개 (4유형 본문 반영)

```
화면 6(결과 공개)을 4가지 유형 버전으로 각각 만들어줘. 유형별 컬러를 메인 강조로.

[유지]
- 진행 단계 인디케이터 (1.검사 / 2.결과 / 3.봉사자증, 2번 활성)

- 유형 설명 박스 + 추천 봉사활동 태그

[유형별 변경 — 각 유형마다 1화면씩, 총 4화면]

· 지식나눔 탐구자 (스카이블루 #6BB5FF)

  - 마이크로 카피: "당신의 따뜻한 경청이 누군가의 세상을 구해요"

### 1.2 화면 7 — 캐릭터 커스터마이징 (대체)

기존 "캐릭터 선택"에서 "캐릭터 커스터마이징"으로 화면 자체가 바뀜.

```
화면 7을 캐릭터 커스터마이징 화면으로 다시 만들어줘.

[구성]
- 상단 진행 인디케이터 (3.봉사자증 활성)

- 가운데: 미리보기 캐릭터 (256x256, 검사 결과 기반 기본값으로 시작)

  · 성별 탭: 여 / 남 (2개)
  · 헤어 탭: 5개 썸네일 (가로 스크롤)
  · 모자 탭: 4개 썸네일

[톤]
화면 6의 유형별 보조 컬러를 헤더 영역에 약하게 깔아 톤 연속성 유지
```

기존 디자인은 행정 정보 위주라 결과 콘텐츠가 빠져있음. 9영역 풀세트로 다시.

```
화면 10(봉사자증 뒷면)을 다음 9영역 구조로 재구성해줘.

A. 헤더 — KB 라이프 로고 (좌상단) + "BACK SIDE" 라벨

C. 마이크로 카피 — 따옴표 디자인의 인용구 박스, 유형별 보조 컬러 배경

G. 마무리 멘트 — "KB 라이프 청소년자원봉사대회, 여러분의 참여를 기다릴게요!" (KB 옐로우 박스)

## 2. 디자인 자산 다운로드 워크플로우

### 2.1 무료 플랜으로도 가능한 기본 export
| 자산 | 방식 | 출력 |
|------|------|------|
| **각 화면 미리보기** | 프레임 우클릭 → "Export" → PNG @2x | 참조용 이미지 |
| **아이콘·소품** | 단일 요소 선택 → "Export" → SVG | `/public/assets/icons/` |
| **캐릭터 부품** | 부품 별 프레임 선택 → "Export" → PNG (투명 배경) | `/public/assets/characters/{F\|M}/` |
| **로고** | KB 로고 프레임 → "Export" → SVG | `/public/assets/logo.svg` |

### 2.2 디자인 토큰 추출
컬러·타이포·간격은 이미 `CLAUDE.md`에 기록되어 있음. Figma 변수가 코드와 어긋나지 않도록 주기적으로 동기화.

```ts
// styles/tokens.ts (생성 권장)
export const tokens = {
  color: {
    kbYellow: "#FFCC00", charcoal: "#1E1E1E", ivory: "#FFF9E6",
    investigator: "#6BB5FF", helper: "#B5A0E5",
    leader: "#FF7E6B", innovator: "#5DD3B0",
  },
  radius: { sm: 8, md: 16, lg: 24 },
  shadow: { card: "0 4px 12px rgba(0,0,0,0.08)" },
  font: { heading: "Pretendard", body: "Pretendard" },
};
```

Tailwind 설정에도 동일한 토큰을 `tailwind.config.ts`의 `theme.extend`에 매핑.

### 2.3 Figma Dev Mode 활용
유료 플랜이라면 Dev Mode에서 각 요소의 CSS·Tailwind 자동 추출. 무료 플랜이면 색상값·간격은 위 tokens를 기준으로 수동 코딩.

### 2.4 Figma Make 코드 export (참고용)
- Figma Make는 React/HTML 코드 export 기능 제공 (플랜 따라 다름)
- 추출된 코드는 그대로 쓰지 말고 **레이아웃·구조 참고용**으로만 사용
- 실제 컴포넌트는 우리 폴더 구조(`/components/...`)와 Tailwind 컨벤션에 맞게 재작성
- 이유: Figma 자동 생성 코드는 절대 위치(absolute) + 인라인 스타일 위주라 반응형·재사용성이 떨어짐

## 3. 캐릭터 부품 PNG export (가장 중요)

캐릭터 합성은 클라이언트 측 PNG 레이어 합성으로 진행한다 (`docs/SPEC.md` 6장 참조). 따라서 부품을 정확한 사이즈·정렬로 export하는 게 핵심.

### 3.1 export 규격
- 모든 부품 동일 viewport: **256 × 256 px** (또는 512 × 512 권장 — 레티나 대응)
- 투명 배경 PNG
- 베이스(얼굴+의상)와 부품(헤어·모자·안경)이 같은 좌표계에 정렬되어야 함

### 3.2 export 체크리스트
1. Figma에서 "기본형" 프레임을 256×256 정사각형으로 통일
2. 헤어/모자/안경 옵션을 각각 별도 프레임으로 분리
3. 모든 옵션 프레임의 캐릭터 위치·크기를 베이스와 동일하게 맞춤
4. 부품만 보이게(베이스 숨김) export → 투명 배경 PNG
5. 파일명: `hair-1.png`, `hair-2.png`, ..., `hat-1.png`, ..., `glasses-1.png`, ...
6. 디렉토리: `/public/assets/characters/F/`, `/public/assets/characters/M/`

### 3.3 충돌 케이스 (모자 × 헤어)
긴 머리 + 모자(특히 비니·볼캡)는 머리가 모자에 가려지는 자연스러운 표현이 필요. 두 가지 방식 중 선택:

**방식 A — 부품 단순 합성 (추천)**
- 모든 모자 부품을 "이마 위쪽만 가리는" 형태로 디자인
- 헤어는 옆머리·뒷머리만 노출되도록 디자인
- 단순 z-index(헤어 < 모자)로 자연스러움 → 별도 처리 X

**방식 B — 헤어×모자 조합 사전 제작**
- 헤어 5종 × 모자 4종 = 20장 헤어 부품을 미리 만듦 (모자 종류별로 가려진 헤어)
- 합성 시 `hair-${모자종류}-${헤어번호}.png` 선택
- 표현 정밀도는 ↑, 자산 수 ↑

지금 받은 그리드 이미지가 방식 A로 봐도 자연스럽게 처리 가능한 수준이라 **방식 A 우선 시도** → 어색하면 방식 B로 보강.

## 4. 단계별 작업 순서 (이 순서로 진행)

1. **Figma Make에 1.1 ~ 1.4 보강 프롬프트 4건 차례로 던지기**
2. 새 디자인 받으면 톤 점검 → OK면 화면별 PNG export
3. **캐릭터 부품 PNG export** (3.2 체크리스트대로) → `/public/assets/characters/`
4. 로고·아이콘 SVG export → `/public/assets/`
5. Next.js 프로젝트 초기화 (`pnpm create next-app`)
6. Prisma 스키마(`docs/SPEC.md` 3장) 그대로 도입 → `pnpm prisma migrate dev`
7. 화면별 컴포넌트 작성 (간단한 화면부터 — 인트로 → 검사 → 결과 → 봉사자증 순)
8. 캐릭터 합성 컴포넌트 + 검사 채점 로직 단위 테스트
9. 통합 테스트 (전체 시나리오 한 번 돌려보기, 폰에서)
10. 어드민 대시보드 + 부하 테스트

## 5. 자주 헷갈리는 포인트

- **Figma 좌표계 ≠ 웹 좌표계**: Figma는 디자인 캔버스 기준 절대 좌표. 웹은 컨테이너 상대 좌표 + flex/grid. 그대로 옮기면 화면 깨짐. 항상 layout으로 재구성
- **Pretendard 적용**: `<link>` 또는 `next/font`로 로드. CDN 사용 시 `https://cdn.jsdelivr.net/gh/orioncactus/pretendard/dist/web/static/pretendard.css`
- **iPhone 14 safe area**: Tailwind `pb-[env(safe-area-inset-bottom)]` 필요. 하단 고정 CTA 가려짐 주의
- **봉사자증 이미지 저장**: `html2canvas`는 한글 폰트·이모지 변환 시 폰트 미적용 이슈. `dom-to-image-more` 또는 SSR canvas 검토
